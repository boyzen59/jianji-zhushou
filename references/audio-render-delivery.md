# 真人、声音与成片

## 出镜与已有录像

章节/小章取自正文真实层级，不能把普通语义段改名“小章”以插入真人。大章从过渡卡结束后的正文第一句计时：

| 位置 | 安排 |
|---|---|
| 大章开头 | 正文0–10秒全屏，10–15秒收为小窗继续；收缩过渡包含在后5秒里 |
| 真实小章开头 | 小窗配合首个完整语义单元，按文案定长 |
| 全片最后结论 | 真人完成结尾，默认全屏 |
| 其他正文 | 只用素材/动效，旁白可继续 |

大章与首小章同起点只安排一次，章不足15秒以真实结束为界。先核对已有录像的台词、位置和有效入点；不把中段台词搬到章头，不机械剪掉每条实拍的前3秒。位置不符或缺录制时先交补录需求，其余工程继续；完整素材/动效工作版可先审阅，但不称为已满足真人要求的最终版。小窗位置见项目theme与[视觉规则](visual-style.md)。

## 录制需求包

按真实出镜缺口从用户长录音切片，不重新合成语音替代。最早交付的每项包含需求ID、REV/章节、中文台词、源录音与源起止、目标录制时长和出镜安排：
- exact：原声精确切片，不添加引导，适合正常时间线。
- guide：3.00秒纯静音＋默认880Hz/0.15秒蜂鸣＋同一exact；台词从3.15秒起。参数写入清单，guide永不进入旁白/成片。
- 已给且符合要求的录制/切片复用；缺长录音或时码时明确缺项，不冒称切片已完成。

脚本入口：scripts/build_presenter_audio.py，参数--output-dir与--ffmpeg。计划示例：

~~~json
{
  "source_audio": "long-narration.wav",
  "segments": [{
    "id": "REC-001", "review_id": "REV-0001", "scene_id": "S0001", "chapter": "CH01",
    "start": 12.0, "end": 27.0, "narration_zh": "实际需要录制的中文台词",
    "presenter_arrangement_zh": "大章开头10秒全屏＋5秒小窗"
  }]
}
~~~

start/end用原长录音时码，不能用加过过渡的成片时码。旧计划缺文稿/关联字段即使能切片，也不是完整录制需求包；补齐实际字段再交付。

## 时基与声音分轨

原音频保持原样，新增过渡写入源时码→成片时码映射；旧项目已有章间停顿时重建或替换，不重复叠加。只有经确认的非正文前导才裁切，不把某项目4.5秒裁切量推广。帧数统一从绝对边界计算，正常句间停顿保留。章卡详见[独立2秒规则](3秒双语标题卡_制作规则.md)。

旁白、AI视频原声、音乐/章节音效分轨。AI画面默认静音，原声单独输出全片对齐48kHz WAV与逐条清单，让用户决定是否保留。计划记录源入点、时长、成片入点；明确无音轨可补静音，缺源/探测失败必须报错，不能混为“无声”。真人原声用于同步或指定旁白替换，不和同一句配音重叠成人声双轨。

scripts/build_ai_video_audio_stem.py按clips计划工作；不支持playbackRate，确有变速先生成同处理的派生素材。Windows长路径/大量输入时分连续时间块处理，跨块片段调整源入点，块内时码归零，再按相同格式顺序拼接；不要一次命令塞全片长路径。每份派生音轨对齐同一总终点，已有旧时间线stem不能直接套新片。

## 交付与恢复

按当前请求交付：前期录制包、分镜表/动效手册；审阅PPT及按需中文Word；需要成片才生成静音编辑母版和旁白/AI原声等分轨。音乐无合适输入可省略，不因此阻断主任务。

编辑母版：MP4、H.264 High、2560×1440、60fps CFR、yuv420p、Rec.709、无音频流与字幕流。无音轨母版是编辑规格，不是额外前3秒静音；如另要带声音成片，按用户选择的轨混合。

build_render_plan.py只为已就绪的新spec建计划，默认拒绝覆盖已有进度；确认需要重建时才用--overwrite并保留自动备份。检查点和分段产物一起复用，数据变动只让受影响段失效；实际生产入口不存在就先实现，不交虚构续跑命令。
